FlyRank Search Intelligence · Capstone Research Paper

Content Refresh Opportunity Scoring

A leakage-aware ranking system for prioritizing which content items deserve human review first.

Decision supportClient-held-out validationRandom ForestRanked action queue

Abstract

Question. Can safe search, content, and engagement signals be used to rank content items that are more likely to be in a declining state, so a reviewer can focus limited review time?

Method. We define a declining label from the observed trend_direction = down field, exclude the label and trend-derived fields from features, compare a transparent staleness-plus-demand baseline with a Random Forest, and validate using a client-held-out split.

Result. On the held-out test set, the Random Forest reached Precision@20 = 0.70, Precision@50 = 0.64, and Precision@100 = 0.62, versus 0.40, 0.38, and 0.38 for the baseline.

Interpretation. The model therefore produced a more concentrated review queue on this measured split, while the ROC AUC of 0.616 shows that discrimination is useful but far from perfect.

Practical output. The final system turns scores and observable conditions into reason-coded recommendations such as review/diagnostic, refresh review, and monitor; these are decision-support suggestions, not guarantees of improvement or causal claims.

1. Introduction / Problem statement

Content teams often have more pages to review than they can inspect manually. The decision supported by this project is simple: which content should a human reviewer examine first?

The goal is not to reconstruct a search engine's ranking algorithm. It is to use the available FlyRank search/content signals to create a repeatable prioritization layer that can surface potentially important items for review.

Research framing: the model estimates an observed declining-state label in the supplied dataset. It does not prove why a page declined, that a refresh will recover performance, or that any feature causes search performance.

The capstone notebook uses data/raw/content_refresh_anonymized.csv, an anonymized FlyRank starter slice. It contains no client names, domains, URLs, private queries, credentials, or raw exports. The analysis works at the content-item level and keeps identifiers only for grouping and review-queue traceability; they are excluded from model features.

The observed trend distribution is: down 16,262; stable 5,962; up 4,388; new 2,236; flat 1,152. Missing values are retained and handled inside the modeling pipeline.

Excluded from features: trend_direction, trend_pct, the target label, content_id, and client_id. Trend-derived fields were excluded because using them would directly leak the target definition.

The paper deliberately describes the exact public-safe slice actually modeled rather than claiming that the 30,000-row starter file is the full warehouse release.

3. Methodology

Label

is_declining_label = 1 when the observed trend_direction equals down; otherwise 0. The resulting overall rate is 54.21%.

Features

Features include search demand, content characteristics, historical impressions/clicks/sessions, content age and freshness, CTR, average position, engagement, scroll, and related categorical tiers. Numeric values are median-imputed and standardized; categorical values are most-frequent imputed and one-hot encoded.

Baseline

The transparent baseline combines percentile-ranked days_since_last_update and search_volume with equal weights: 0.5 staleness + 0.5 demand.

Model

A Random Forest classifier with 300 trees, balanced subsampling, minimum leaf size 2, and fixed random seed 42 was trained in a preprocessing pipeline.

Validation

A single 80/20 client-held-out split was used. Training contained 25 clients and 23,837 rows; the test set contained 7 clients and 6,163 rows. Client overlap was zero. The test decline rate was 51.10%.

Leakage audit

The final feature list was checked to ensure the label, trend direction, trend percentage, content identifier, and client identifier were absent. The pipeline also fits imputers, encoders, and the model on training data before scoring the held-out test set.

5. Limitations & honest framing

  • The evaluation uses one client-held-out split; it is not a universal estimate of production performance.
  • The label is a dataset-defined observed state, not a causal explanation of decline.
  • Random Forest probabilities are ranking signals; they should not be read as calibrated probabilities without a calibration study.
  • The model cannot establish that refreshing, rewriting, merging, or pruning content will improve search performance.
  • The starter slice is anonymized and public-safe; it does not expose client names, domains, private queries, URLs, or raw exports.
  • No result here is evidence about Google's proprietary ranking algorithm.
Preferred language: observed, measured, associated, directional, ranked, prioritized, decision-support. Avoid causal language such as “causes,” “will recover,” or “proves Google's algorithm.”

6. Ranked content recommendations

The action engine is intended to create a human-review queue. A high score means “review earlier,” not “take the action automatically.” Reason codes make the queue auditable.

PriorityRecommendationReason code / evidenceHuman check
1Review / diagnoseHigh model score, especially where recent search performance signals suggest attention is warrantedCheck intent fit, content quality, SERP context, and recent changes
2Review refresh opportunityHigh staleness + meaningful demand or a strong model scoreConfirm information is outdated before editing
3MonitorLow demand, limited evidence, or weaker scoreWatch future observations before spending review effort
4Protect / avoid unnecessary changeStable/strong observed performance outside the urgent review queueVerify there is a concrete reason to change the content

The deployed notebook also produces a ranked queue with rank, content_id, model score, action, staleness, demand, trend state, CTR, engagement, and impressions. Client names and private identifiers are not exposed.
